1. 全体アーキテクチャ：3大エージェントプレーンと共通MCPバス

これまで、異なるAIエージェントツール（Geminiアプリ、IDE型エージェント、ローカル自律エージェント）は個別にツール設定や拡張機能を持つのが一般的であり、ツール追加や認証情報の管理が多重化する問題がありました。

本システムでは、すべてのエージェントが単一の中央MCP設定（mcp_config.json）を参照し、同一のローカルツール群・外部API・クラスタ操作モジュールを共有する「Universal MCP Bus アーキテクチャ」を採用しています。

3. ステップ2：macOS ターミナル操作MCPの完全実装（Python FastMCP）

エージェントに「Macを操作させる」上で最大の難所は、環境変数やPATHが非ログインシェルで欠落し、pyenvやhomebrew、SSH設定が正常に解決されない点にあります。

本実装では、FastMCPを採用し、ユーザーの~/.zprofileおよび~/.zshrcを透過的にプリロードする堅牢な実行ラッパーを構築しました。

macos-terminal-mcp/server.py 実装コード

#!/usr/bin/env python3
# macOS Terminal & Shell Execution MCP Server
import os
import subprocess
import sys
from pathlib import Path
from typing import Any, Dict, Optional
from mcp.server.fastmcp import FastMCP

mcp = FastMCP(
    "macos-terminal",
    instructions="macOS上のローカルコマンド（Zsh）およびリモートクラスタ（SSH）を実行する統合ツール"
)

@mcp.tool()
def execute_command(command: str, cwd: str = "~", timeout: int = 120) -> Dict[str, Any]:
    """macOSのzsh経由でシェルコマンドを実行し、結果を返却する。"""
    expanded_cwd = os.path.expanduser(cwd)
    if not os.path.exists(expanded_cwd):
        return {"success": False, "error": f"Directory not found: {expanded_cwd}", "exit_code": 1}

    # ユーザーのログイン環境（PATH, alias等）を確実にロードして実行
    shell_cmd = f"source ~/.zprofile 2>/dev/null; source ~/.zshrc 2>/dev/null; {command}"

    try:
        proc = subprocess.run(
            ["/bin/zsh", "-c", shell_cmd],
            cwd=expanded_cwd,
            capture_output=True,
            text=True,
            timeout=timeout,
            env=os.environ.copy()
        )
        return {
            "success": proc.returncode == 0,
            "exit_code": proc.returncode,
            "stdout": proc.stdout,
            "stderr": proc.stderr,
            "cwd": expanded_cwd
        }
    except subprocess.TimeoutExpired as e:
        return {"success": False, "error": f"Timeout ({timeout}s)", "exit_code": -1}
    except Exception as e:
        return {"success": False, "error": str(e), "exit_code": 1}

@mcp.tool()
def ssh_command(host: str, command: str, user: Optional[str] = None, timeout: int = 60) -> Dict[str, Any]:
    """Tailscale / SSH経由でリモートGPUクラスタノードにコマンドを発行する。"""
    target = f"{user}@{host}" if user else host
    ssh_args = [
        "ssh",
        "-o", "ConnectTimeout=10",
        "-o", "BatchMode=yes",
        "-o", "StrictHostKeyChecking=accept-new",
        target,
        command
    ]
    try:
        proc = subprocess.run(ssh_args, capture_output=True, text=True, timeout=timeout)
        return {
            "success": proc.returncode == 0,
            "exit_code": proc.returncode,
            "target": target,
            "stdout": proc.stdout,
            "stderr": proc.stderr
        }
    except Exception as e:
        return {"success": False, "error": str(e), "exit_code": 1}

@mcp.tool()
def open_in_terminal(command: str) -> Dict[str, Any]:
    """AppleScriptを用いてmacOS Terminal.appの新規ウィンドウを可視起動し実行する。"""
    escaped = command.replace('\\', '\\\\').replace('"', '\\"')
    apple_script = f'''
    tell application "Terminal"
        activate
        do script "{escaped}"
    end tell
    '''
    try:
        subprocess.run(["osascript", "-e", apple_script], capture_output=True, text=True, timeout=10)
        return {"success": True, "message": "Opened new Terminal window"}
    except Exception as e:
        return {"success": False, "error": str(e)}

@mcp.tool()
def get_system_info() -> Dict[str, Any]:
    """CPU負荷、空き容量、稼働時間、Tailscale接続状態を取得する。"""
    uptime = subprocess.run(["uptime"], capture_output=True, text=True).stdout.strip()
    disk = subprocess.run(["df", "-h", "/"], capture_output=True, text=True).stdout.strip()
    return {"success": True, "uptime": uptime, "root_disk": disk}

if __name__ == "__main__":
    mcp.run()

4. ステップ3：セキュリティ境界とサンドボックス防衛設計

AIエージェントにシェル実行権限を与える際、最も警戒すべきは「誤った一括削除コマンドの暴走」や「セキュリティ保護領域への無制限アクセス」です。

  1. macOS SIP（System Integrity Protection）との整合性:
    macOSネイティブの保護領域（/System、/usr/binなど）や、TCC（Transparency, Consent, and Control）が保護する「連絡先」「カレンダー」「写真」等へのアクセスはOSカーネルが厳格に拒否するため、AIが暴走しても基幹システムが破壊されるリスクは構造的に排除されています。
  2. エージェント実行ユーザーの分離:
    Geminiやサブプロセスの実行コンテキストは、必要最小限の権限を持つサンドボックス・ユーザーまたはプロジェクトディレクトリに限定し、秘密鍵やマスターパスワードはmacOSキーチェーン（securityコマンド連携）または環境変数経由でのみ受け渡します。
  3. タイムアウト・リソース制限（cgroup / ulimit）:
    無限ループやメモリ枯渇を防ぐため、すべてのコマンドに明示的なtimeoutパラメータ（既定120秒）を設定し、応答がないプロセスはSIGTERM/SIGKILLで確実に刈り取ります。

5. 実践検証：GeminiチャットからMacとリモートGPUを自律操作する

この仕組みを導入したGeminiアプリでは、ユーザーが「@macos-terminal Z790-AL の GPU 状態を確認して」と1行チャットで話しかけるだけで、以下の自律アクションが瞬時に実行されます。

  1. Geminiがプロンプトを解析し、MCPツールssh_commandの呼び出しを選択。
  2. 引数としてhost: "Z790-AL"、command: "nvidia-smi"を透過送信。
  3. ローカルMacのFastMCPサーバーがTailscaleメッシュを経由してリモートノード（RTX 4070 Ti SUPER ＋ RTX 3060）へSSHログイン。
  4. VRAM使用量（14,757 MiB / 10,571 MiB）や稼働中プロセス（Strata推論エンジン）を解析し、チャット画面に見やすい表組みとして即座に返却。

さらに、AppleScript連携（open_in_terminal）を使えば、GUI画面上でユーザーが目視確認できる形でシェルジョブを実行させたり、excel-liveを呼び出してMac上のMicrosoft Excelシートにリアルタイムで数式やデータを書き込ませるなど、まさに「Gemini Spark」が目指すPC自動化が、今すぐ手元のMacで完全に動作します。

6. まとめ：自律PCコワーキングの新時代へ

オープンなプロトコルであるMCPを活用することで、独自モデルや特定の商用サービスに縛られることなく、手持ちのMacを最強の自律エージェントステーションへとアップグレードできます。

  • 統合性: Gemini、Antigravity、Hermesが同じツール・同じ環境を共有。
  • 拡張性: Python数行で新しいMCPツールを追加し、即座に全エージェントで利用可能。
  • ローカル完結: 機密コードやローカルファイルをクラウドにアップロードせず、自前のマシンパワーとクラスタで処理。
