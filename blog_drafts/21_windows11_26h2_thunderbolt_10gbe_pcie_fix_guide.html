ドライバの再インストールを試みても「対応するハードウェアが見つかりません」と跳ね返され、デバイス自体がPCIeツリーから脱落している状態でした。 この壊滅的な状況から、「2枚のPCIeカードの物理スロットを入れ替える」というハードウェア的アプローチによって完全復活を遂げ、さらにその後に連鎖して発生した「USB/IPのコード52署名エラー」や「外付けThunderbolt SSDのホットプラグ認識不全（ゴースト残存）」までを完治させた全手順を技術ログとして記録します。

1. システム構成と直面したトラブルの全貌

1.1 動作環境スペック

マザーボード MSI PRO Z790-A WIFI（Intel Z790チップセット、UEFI: Click BIOS 5）
CPU Intel Core 第13/14世代プロセッサ
OS Windows 11 Pro（バージョン 26H2、PowerShell 7.x 稼働）

1.2 26H2アップデート後に連鎖した3大トラブル

  1. 主障害：10GbE LANカードの完全消失とThunderboltカードの未接続沈黙
    Windows 11 26H2の適用直後、有線LAN通信が切断。デバイスマネージャーの「ネットワーク アダプター」一覧から10GbEカード自体が消滅しました。同時にThunderboltコントロールセンターも「未接続」になり、ThinkPadドック（40AN）経由の画面出力、オーディオ、有線LANがすべて停止しました。
  2. 従属障害A：WSL2用USB/IPドライバの「コード52（デジタル署名検証エラー）」
    ハードウェア復旧後、WSL2へUSB機器をマウントしようとしたところ、usbipd-win の仮想コントローラーがドライバ署名検証エラー（コード52）を起こし、デバイスの転送が不能になりました。
  3. 従属障害B：Thunderbolt SSDホットプラグ時の「ゴースト残存バグ」
    Thunderbolt SSDを安全に取り外して別のSSDを接続しても、エクスプローラー上に抜いたはずの古いSSDのドライブ名が残り、手動でデバイスの再スキャンを行わないと新しいドライブが認識されなくなりました。

2. 【真相解明】なぜ10GbE LANとThunderboltカードが同時に消えたのか？

2.1 MSI PRO Z790-AのPCIeスロット仕様

トラブルの原因を突き止めるには、マザーボードの基板配線とチップセット（PCH）の内部構造を確認する必要があります。 MSI PRO Z790-Aの拡張スロットは、上から順に以下の構成になっています。

  • PCI_E1：PCIe 5.0 x16スロット（CPU直結、グラフィックボードが占有）
  • PCI_E2：PCIe 3.0 x1スロット（Z790 PCH接続）
  • PCI_E3：PCIe 4.0 x4スロット（外見はx16形状、内部配線はPCH接続x4）
  • PCI_E4：PCIe 4.0 x4スロット（外見はx16形状、内部配線はPCH接続x4）

グラフィックボード以外の高速カード（x4動作を要求する10GbEカードやThunderboltカード）を増設する場合、下段の PCI_E3 と PCI_E4 を使用することになります。 外見上、この2つのスロットは同じ仕様に見えますが、Z790チップセット内部のDMI 4.0 x8共通帯域とHSIO（高速I/O）レーンを基板上のM.2スロットやSATAポートと共有しています。

2.2 26H2のPCIe電源管理強化と初期化競合

Windows 11 26H2では、プラットフォーム全体の省電力性向上のため、PCIeの電源管理（Modern Standby / ASPM）の厳格化と、ブート時におけるPCIe列挙タイマーの短縮が実施されました。

従来の23H2等では、ハードウェアの初期化に多少の遅延があってもOSカーネルが待機して認識していました。 しかし26H2では、起動時のごくわずかな制限時間内にPCIeリンクが安定確立しない場合、OSカーネルはそのポートへの給電ステートを落とし（D3cold）、バス列挙から除外する動作をとるようになりました。

当時のスロット配置は以下の通りでした。

❌ 障害発生時の物理配置（変更前）:
・PCI_E3（上段スロット）：10Gbps LAN拡張カード
・PCI_E4（下段スロット）：Thunderbolt 4拡張カード（JTBT1ヘッダー配線）

Thunderbolt 4拡張カードは、単にスロットから給電されるだけでなく、マザーボードの「JTBT1ヘッダー」を介してPCHのGPIOピンと専用の初期化ハンドシェイク（Force PowerおよびHot Plug信号）を行います。 この配置では、最下段のThunderboltカードがGPIOハンドシェイクを行おうとするのと同時に、上位チャネルにある10GbEカードがPHYのリンクネゴシエーションを開始し、PCH内部で初期化の競合（レースコンディション）が発生していました。

26H2の厳格なタイマーにより、PCH側のPCIeルートポートがタイムアウトと判定され、両スロットへの給電が停止。 その結果、10GbEカードはOSから存在が消え、Thunderboltカードもリンクアップできずに「未接続」で固まるという共倒れが起きていました。

3. 【最大の決定打】PCIeスロットの物理差し替えで大逆転

デバイスがPCIeバス列挙の段階で脱落している以上、OS上でドライバを再インストールしても解決しません。 根本的な原因が「PCH内部でのハードウェア認識順序と初期化タイミングの衝突」にあると判断し、2枚のカードを挿すスロットを物理的に入れ替えることにしました。

3.1 物理作業手順

  1. 残留電荷の完全放電
    PCをシャットダウンし、電源ユニットの主スイッチをオフにしてコンセントを抜きます。PC前面の電源ボタンを10回以上連打し、さらに30秒間長押しして、基板コンデンサの残留電荷を完全に放電させます。
  2. スロットの物理スワップ（入れ替え）
    2枚の拡張カードを取り外し、スロットを入れ替えて装着します。
    ✅ 解決時の物理配置（変更後）:
    ・PCI_E3（上段スロット）：Thunderbolt 4拡張カード
    ・PCI_E4（下段スロット）：10Gbps LAN拡張カード
    Thunderboltカードの移動に合わせて、JTBT1ケーブルおよび内部USBヘッダーケーブルも配線し直します。
  3. PCの起動と認識確認
    配線を確認し、PCの電源を投入します。

3.2 スロット入れ替えによる効果

スロットを入れ替えて起動した直後、Windowsのハードウェア検出音が鳴り響きました。

  • タスクバーの地球儀マークが消え、有線ネットワーク通信が即座に復旧。
  • デバイスマネージャーに10GbEネットワークアダプターが正常表示。
  • ThinkPad Thunderbolt 3 Dock（40AN）のLEDが白色点灯に変わり、Thunderboltコントロールセンターで「接続済み」と認識。ドック経由の画面やUSB機器が一斉に動作再開。

PCHのスキャン順序において上位に位置する PCI_E3 にThunderboltカードを配置したことで、GPIOハンドシェイクが先行して安定完了し、続いて PCI_E4 の10GbEカードが認識されるという、正しい初期化シーケンスが成立しました。

4. 復旧後に連鎖した「USB/IP コード52署名エラー」の根絶

ハードウェアが復旧した直後、WSL2環境へUSBシリアル機器を転送しようとしたところ、usbipd でエラーが発生しました。 デバイスマネージャーを開くと、「システム デバイス」内の「USB/IP VHCI」に黄色い感嘆符（コード52: デジタル署名の検証エラー）が表示されていました。

4.1 原因調査：古いドライバ（oem41.inf）の競合

UEFIでSecure Bootが有効な環境では、テスト署名モード（bcdedit /set testsigning on）はブロックされます。 また、winget install dorssel.usbipd-win を実行しても「最新バージョンがインストール済み」と表示され改善しませんでした。

Windowsのドライバストア（Driver Store）内部を調査するため、管理者権限のPowerShellで以下のコマンドを実行しました。 

pnputil /enum-drivers | Select-String -Pattern "usbip" -Context 2,4

出力結果：

公開名:      oem41.inf

    元の名前:    usbip_vhci.inf

    プロバイダー名: Open Source

    クラス名:    System

    ドライバー バージョン: 09/03/2019 0.3.0.0

過去に手動導入した2019年製の古い未署名ドライバ（oem41.inf）がドライバストアに残存しており、Windowsが最新の署名済みドライバではなくこの古いドライバを優先してバインドしていたことが原因でした。

4.2 解決手順

  1. 古い未署名ドライバパッケージを強制削除します。 
    pnputil /delete-driver oem41.inf /uninstall /force
  2. デバイスマネージャーを開き、「システム デバイス」内の黄色い警告が出ている「USB/IP VHCI」を右クリックして「デバイスのアンインストール」を実行します。
  3. 署名済みの最新パッケージを強制再適用します。 
    winget install dorssel.usbipd-win --force
  4. 状態を確認します。 
    usbipd list

警告マークが消滅し、すべてのUSB機器が Not shared で正常に列挙され、WSL2へのアタッチも復旧しました。

5. Thunderbolt SSDホットプラグ「ゴースト残存バグ」の恒久対策

最後に立ちはだかったのが、外付けThunderbolt SSDを取り外したあと、別のSSDを挿しても以前のドライブ名が残り続ける現象です。 手動で「ハードウェア変更のスキャン」を実行しないと新しいSSDがマウントされませんでした。

5.1 MountMgrキャッシュパージ（DiskPart）

Windowsのボリュームマウントマネージャー（MountMgr）が、レジストリ（HKLM\SYSTEM\MountedDevices）に古いボリュームのGUIDとドライブ文字を保持し続けていたことが要因でした。 DiskPartを用いてキャッシュを一括消去します。 

# 管理者権限のPowerShellでDiskPartを起動

    diskpart


    # DiskPartプロンプトで実行

    automount enable

    automount scrub

    exit

「マウントされていないボリュームの以前のマウント ディレクトリのクリーンアップが成功しました」と表示されれば、古いマウント情報の消去は完了です。

5.2 高速スタートアップの完全無効化

高速スタートアップが有効だと、不完全なPCIeルートポートの割り込み状態が次回起動へ引き継がれてしまいます。 ハイバネーションごと完全に無効化します。 

powercfg -h off

5.3 MSI Click BIOS 5 の設定最適化

PC起動時に Delete キーを押してMSI Click BIOS 5に入り、Advanced Mode (F7) で以下のパラメータを確定させます。

設定階層 / 項目名 設定値 目的・動作
Settings > Advanced > Intel(R) Thunderbolt
Discrete Thunderbolt(TM) Support		 Enabled 拡張カードのTBチップセットを有効化
Settings > Advanced > Intel(R) Thunderbolt
Thunderbolt OS Support		 Enabled OSネイティブのACPIホットプラグ制御へ委譲
Settings > Advanced > PCIe/PCI Sub-system Settings
PCIe Native Power Management		 Disabled ハードウェア省電力の競合デッドロックを防止

設定後、F10 キーを押して変更を保存し再起動します。

5.4 ドック経由と直挿しの切り分け

ThinkPad Thunderbolt 3 Dock（40AN）を経由している場合、ドック内部のコントローラーが下流SSDのリンクダウン通知をドロップさせるバグが知られています。 SSDの差し替え時に違和感がある場合は、PC本体背面（カード直結ポート）への直接接続で再現性を確認し、ドック側のファームウェア更新（Lenovo公式ユーティリティ）を適用してください。

6. システム健全性を一括確認する保守PowerShellスクリプト集

Windows Updateやドライバ更新後にシステムの健全性を一発で確認できる、管理者権限PowerShellワンライナー集です。 

# 1. 10GbEを含むネットワークアダプターのリンク速度とステータス

    Get-NetAdapter | Select-Object Name, InterfaceDescription, Status, LinkSpeed


    # 2. エラー（コード52等）を起こしているPnPデバイスの抽出

    Get-PnpDevice | Where-Object { $_.Status -eq 'Error' -or $_.Problem -ne 'CM_PROB_NONE' } |

        Select-Object FriendlyName, InstanceId, Status, Problem


    # 3. 認識されているディスクドライブの一覧

    Get-Disk | Select-Object Number, FriendlyName, OperationalStatus, HealthStatus, BusType


    # 4. usbipdの稼働状態

    usbipd list

万が一、外付けドライブの認識に一時的な引っかかりを感じた場合は、再起動せずに以下の2行を実行することで、デバイス構成とディスクキャッシュを即時更新できます。 

pnputil /scan-devices

    Get-Disk | Update-Disk

7. まとめ：物理層と論理層の両面から切り分ける

今回のトラブルシューティングを通じて得られた知見を整理します。

対象階層 直面した症状と根本原因 決定打となった解決策
物理ハードウェア層 10GbEとThunderboltが同時消失（26H2タイマーとPCH配下の初期化競合） PCI_E3とPCI_E4のスロット物理入れ替え
ドライバ層（KMDF） USB/IPのコード52エラー（過去のoem41.inf未署名ドライバ残存） pnputilで旧ドライバ強制削除 ＆ usbipd-win再導入

Windowsの大型アップデート（26H2）後に「拡張カードが見えなくなった」「ネットワークが繋がらない」という事象に遭遇した際、OSの設定やドライバだけを操作しても解決しない場合があります。 マザーボードのPCIe配線トポロジーとチップセットの初期化順序に立ち返り、物理スロットの配置を見直すことが、極めて強力な解決策になります。
