Many Requests）、混雑時のレイテンシ増大（応答が10秒以上停止する現象）に直面し、エージェントの自律ワークフローが途中で停止する事態が頻発していました。 2. **Z790側Hermes Agentの「Strata QwenによるGPU専有・衝突問題」** * Z790上のエージェント頭脳は、自作GPUクラスタ（RTX 4070 Ti SUPER 16GB ＋ RTX 3060 12GB、計28GB VRAM）を活用した「Strata Engine（Qwen 3.8 / Qwen2.5系）」を直接利用していました。 * しかし、単一のStrataインスタンスが28GBのVRAM空間とCUDAストリームを一体で専有してしまうため、長文執筆や重いリファクタリングタスクが走っている間、Z790上の他のツール（YomiToku日本語OCR、埋め込みベクトル生成、別プロセスの対話）が完全にブロックされ、マシン全体が1つの処理に縛られる現象が起きていました。 3. **放置されていた「RTX 4060（8GB）」という遊休資産の存在** * Z790の筐体内には、Ada Lovelace世代の高効率GPUである「RTX 4060（8GB / GPU 0）」が搭載されていながら、適切な役割が与えられず遊休化していました。 ### 1.2 導き出された最適解：「3階層ヘテロジニアス推論トポロジー」 この課題に対する最も合理的で完成度の高い解決策は、**「RTX MacBook Air側Hermes Agentの再設計：OpenRouter依存からの完全脱却 ### 3.1 なぜOpenRouter DeepSeek単一運用は破綻するのか MacBook Air単体でのエージェント運用において、OpenRouterのDeepSeekを利用することは一見手軽に見えますが、自律エージェント特有のワークフローにおいて以下の構造的欠陥を抱えていました。 * **思考型エージェントのトークン爆発:** Hermes Agentは、1回の指示に対して内部で思考（Reasoning）、ツール探索、引数生成、エラー訂正など複数回のLLMコールを自律的に繰り返します。1つのタスクで5〜10回のAPI呼び出しが短時間（数十秒以内）に集中するため、OpenRouterの「1分あたりのリクエスト上限（RPM）」に即座に抵触します。 * **混雑時の429エラーと長時間の沈黙:** 米国のピークタイム等でOpenRouterのバックエンドが混雑すると、HTTP 429や503エラーが返り、エージェントが「リトライ待ち」のままフリーズします。外出先MacBookの貴重なバッテリーと作業時間が空費される結果となっていました。 ### 3.2 解決手順：Tailscale経由でZ790のRTX 4060をプライベート頭脳化する MacBook AirのHermes Agentの設定（`~/.hermes/config.yaml` または ACP接続設定）を改修し、優先接続先を自宅Z790のRTX 4060へ向けます。 ```yaml # MacBook Air側 Hermes Agent 推論プロバイダ設定 (~/.hermes/config.yaml) model_provider: "custom_openai_compatible" base_url: "http://z790:11434/v1" # Tailscale経由のZ790 (RTX 4060専用ポート) model_name: "qwen2.5-coder:7b-instruct-q4_K_M" temperature: 0.2 max_tokens: 4096 timeout: 60 # 多層フォールバック設定 (Tier 2 & Tier 3) fallback_providers: - name: "bc250_lane" base_url: "http://bc250:8080/v1" # AMD BC-250 (41W夜間・救済レーン) model_name: "phi-4:14b-q4_K_M" - name: "openrouter_emergency" base_url: "https://openrouter.ai/api/v1" model_name: "deepseek/deepseek-chat" api_key: "sk-or-v1-..." ``` * **Tailscaleによる極小オーバーヘッド通信:** TailscaleのWireGuardトンネルにより、外出先MacBook Airから自宅Z790への通信遅延はわずか数ミリ秒（宅内LANなら1ms以下、外出先テザリングでも10〜20ms程度）です。クラウドAPI（往復200〜500ms）と比較して圧倒的にレスポンスが向上します。 * **トークン完全無料・レートリミットゼロ:** 自宅のハードウェアを叩くため、分間に100回リクエストを投げようと、10万トークンを消費しようと、429エラーが発生することは物理的にあり得ません。 --- ## 4. Z790（Windows 11）側GPU専有問題の根本解決：物理スロット分離と独立サービング ### 4.1 なぜ従来のStrata QwenはGPUを専有してしまったのか 従来のZ790環境では、RTX 4070 Ti SUPER（16GB）とRTX 3060（12GB）を1つの推論プロセスにまとめ、大モデル（Qwen 14B〜32B）をロードしていました。 この構成では、以下の問題が生じます。 1. **CUDAコンテキストのロック:** 1つのプロセスが推論を実行している最中は、GPUの計算コアがビジー状態となり、外部からの新規リクエストはキューに積まれて待たされます。 2. **メモリの断片化とOOMの連鎖:** 巨大なコンテキスト長を持つ記事執筆タスクが走ると、28GBのVRAMの大部分がKVキャッシュで埋め尽くされ、他のプロセス（画像OCRや軽量判定）が割り込むメモリの余地がなくなります。 ### 4.2 解決手順：Windows 11におけるGPUデバイスID分離 Windows 11において、GPUの役割を物理デバイスID（`CUDA_VISIBLE_DEVICES`）レベルで完全に切り離し、独立した推論デーモンを2系統同時に起動します。 ```text 【Z790 (Windows 11) 内部のGPU分離アーキテクチャ】 [PCIeスロット配置と論理分離] ├─ GPU 0: RTX 4060 (8GB) ────────── 独立利用: Port 11434 (Ollama for Windows) │ 【MacBook & Z790 エージェント即応頭脳】 │ ├─ GPU 1: RTX 4070 Ti SUPER (16GB) ┐ 統合利用: Port 8000 (Strata Engine) └─ GPU 2: RTX 3060 (12GB) ┘ 【重い開発・長文記事執筆専用レーン】 ``` #### デーモン1：RTX 4060専用 即応エージェントエンジン（Port 11434） * **対象GPU:** `CUDA_VISIBLE_DEVICES=0`（RTX 4060のみを認識） * **バインドポート:** `0.0.0.0:11434` * **ロードモデル:** `qwen2.5-coder:7b-instruct-q4_K_M` * **常駐設定:** メモリに常時アンロードせず固定（`OLLAMA_KEEP_ALIVE=-1`） * **用途:** MacBook AirおよびZ790ローカルのHermes Agentのメイン対話、日常のコマンド実行、FastMCPツール呼び出し。 #### デーモン2：4070TiS＋3060統合 ヘビー演算Strataエンジン（Port 8000） * **対象GPU:** `CUDA_VISIBLE_DEVICES=1,2`（4070TiSと3060のみを認識、4060は不可視化） * **バインドポート:** `0.0.0.0:8000` * **ロードモデル:** `qwen2.5-coder:32b-instruct-q4_K_M` または `Qwen 3.8 Flash Next` * **用途:** 10,000字規模の長文ブログ執筆パイプライン、数千行のコードリファクタリング、深い論理思考タスク。 この物理分離により、**「Strataが28GBのVRAMをフルに使って2万字の記事を10分間かけて猛烈に執筆している最中」であっても、MacBook側のHermes Agentは全く影響を受けず、RTX 4060を使って秒速70トークンでサクサクと対話やファイル操作を並行実行できる** という完全な独立並列コワーキングが実現しました。 --- ## 5. 実装・導入の具体的手順（Windows 11完全設定マニュアル） 本最適解を導入するための、Windows 11上での実際の設定コマンドと構成ファイルです。 ### 5.1 ステップ1：Ollama for Windowsのインストール 公式サイトから `OllamaSetup.exe` をダウンロードしてインストールします。 インストール完了後、タスクトレイ（右下の時計横）にあるアルパカアイコンを右クリックし、「Quit Ollama」で一度終了させます。 ### 5.2 ステップ2：RTX 4060（GPU 0）専用起動バッチの作成 `C:\Users\thest\start_ollama_4060.bat` を作成し、以下を記述します。 ```bat @echo off set CUDA_VISIBLE_DEVICES=0 set OLLAMA_HOST=0.0.0.0:11434 set OLLAMA_KEEP_ALIVE=-1 set OLLAMA_NUM_PARALLEL=2 "C:\Users\thest\AppData\Local\Programs\Ollama\ollama.exe" serve ``` * `set CUDA_VISIBLE_DEVICES=0`: RTX 4060（GPU 0）のみをOllamaに割り当てます。 * `set OLLAMA_HOST=0.0.0.0:11434`: 外部（MacBook Air等）からTailscale経由でアクセス可能にします。 * `set OLLAMA_KEEP_ALIVE=-1`: モデルをVRAMに常時保持し、アンロード遅延を防ぎます。 ### 5.3 ステップ3：モデル取得と動作確認 バッチを実行して待機させ、別のコマンドプロンプトで以下を実行します。 ```cmd set OLLAMA_HOST=127.0.0.1:11434 ollama pull qwen2.5-coder:7b-instruct-q4_K_M ``` ダウンロード後、テスト対話を実行してGPU 0のみが使用されていることを `nvidia-smi` で確認します。 ### 5.4 ステップ4：Windows Defenderファイアウォールの受信許可 MacBook AirからTailscale経由でPort 11434に接続できるよう、管理者権限のPowerShellで以下を実行します。 ```powershell New-NetFirewallRule -DisplayName "Ollama RTX4060" -Direction Inbound -LocalPort 11434 -Protocol TCP -Action Allow ``` ### 5.5 ステップ5：MacBook Airからの導通および推論実測 MacBook Airのターミナルから接続を確認します。 ```bash # タグ一覧の取得確認 curl http://z790:11434/api/tags # 実推論テスト curl http://z790:11434/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{ "model": "qwen2.5-coder:7b-instruct-q4_K_M", "messages": [{"role": "user", "content": "自律エージェントの準備は整いましたか？短く答えてください。"}] }' ``` 実測結果として、ミリ秒単位で即座に応答（Completion Tokens: 3、Total Tokens: 50、Cached Tokens: 24）が返ることが確認されました。 --- ## 7. 徹底検証Q&A：ハードウェア構成と運用の疑問に答える（8選） ### Q1: Z790マザーボードに3枚のGPU（4060, 4070TiS, 3060）を挿すスペースとPCIeレーンは足りますか？ **A:** 一般的なZ790マザーボードは、最上段にPCIe 5.0 x16（CPU直結）、下段にPCIe 4.0 x4（チップセット経由）スロットを複数備えています。LLMの推論処理はモデル重みをVRAMにロードした後はGPU内部のメモリ帯域で計算が完結するため、下段スロット（x4接続）であっても推論速度（tok/s）の低下は実測上1〜2%未満にとどまり、全く問題なく運用できます。 ### Q2: 3枚のGPUを同時に稼働させた場合の電源容量（PSU）の目安は？ **A:** 4070TiS（約285W）＋ 3060（約170W）＋ 4060（約115W）＋ CPU・システム（約150W）＝ ピーク合計で約720Wです。850W〜1000Wの電源ユニット（Gold認証以上）を搭載していれば十分安全圏です。日常の推論稼働時では3枚が同時に100%全開になる瞬間は稀であるため、日常のシステム消費電力は250W〜350W程度で極めて安定して推移します。 ### Q3: MacBook AirのHermes Agentから見て、7Bモデルで知能不足を感じることはありませんか？ **A:** 日常のファイル整理、OCR結果のパース、シェルコマンドの実行、FastMCPツールのルーティングにおいて、Qwen2.5-Coder 7Bは実務上の知能不足を感じる場面はほぼありません。もし数千行のアーキテクチャ設計や難解な数理アルゴリズムが必要な場合のみ、プロンプト内で「Strata（32B）レーンを使用せよ」と指定してPort 8000へルーティングする二段構えが最もスマートです。 ### Q4: OpenRouterのDeepSeek-R1（推論特化モデル）のような「深い思考」をローカルで使いたい場合は？ **A:** RTX 4060（8GB）上に `deepseek-r1-distill-qwen:7b` をロードすることで、思考プロセス（`...`）を含めた自律推論がローカル完結で動作します。ただしエージェント運用では思考が長くなりすぎるとツール実行までの時間が増えるため、日常運用には標準の `qwen2.5-coder:7b`、難問解決には `deepseek-r1-distill-qwen:7b` を切り替える設定が適しています。 ### Q5: Tailscale経由でのローカル推論ストリーミングは通信が途切れませんか？ **A:** Tailscaleは端末同士をダイレクトにP2P接続（NAT越え通信）するため、宅内LANであれば物理Wi-Fi/有線LAN速度（1Gbps〜2.5Gbps）で直結され、クラウド経由よりも遥かに安定します。外出先のモバイル回線であってもWireGuardプロトコルの堅牢性により、トンネルが切断されることなくスムーズにトークンが流れてきます。 ### Q6: Windows 11を再起動した際、自動でOllamaは立ち上がりますか？ **A:** `Windowsキー + R` → `shell:startup` で開く「スタートアップ」フォルダに `start_ollama_4060.bat` のショートカットを配置しておくことで、PC起動・ログオン時に自動でバックグラウンド常駐します。 ### Q7: AMD BC-250のVulkan推論とZ790のNVIDIA CUDA推論で、プロンプトの互換性に違いはありますか？ **A:** 全くありません。いずれもOpenAI互換のREST API（`/v1/chat/completions`）を標準インターフェースとして公開しているため、Hermes Agent側からは接続先URLを変更するだけで、全く同一のJSONリクエスト・レスポンスで対話を継続できます。 ### Q8: 将来的にモデルをさらに大型化したい場合、この構成はどう拡張できますか？ **A:** 4070TiS（16GB）＋ 3060（12GB）の28GBプレーンに将来70Bクラス（4bit/EXL2、約38GB）を載せたい場合は、RTX 4060（8GB）を一時的に統合して「16GB＋12GB＋8GB＝合計36GB」のトリプルGPU Pipeline並列に切り替えることも技術的に可能です。普段は分離して即応性を確保し、特別な大型バッチ時のみ合体させるという柔軟な運用が可能です。 --- ##
