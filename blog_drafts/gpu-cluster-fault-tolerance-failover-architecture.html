自宅サーバーやローカルGPU環境で推論エンジンを常時稼働させる際、避けて通れないのが「ハードウェアのクラッシュ、OOM（メモリ不足）、長時間のバッチ処理によるビジー（占有）状態」です。

私たちの「AIリビングラボ」では、日常の高速対話や長文ドラフトを担う「Strata（z790-al: RTX 4070TiS 16GB + RTX 3060 12GB）」と、35B MoEモデルや夜間バッチを担う「AMD BC-250（40CU / 16GB GDDR6）」の2系統ノードが稼働しています。しかし、一方が重いタスクで塞がったり、プロセスが不意に落ちた場合、エージェントやユーザーの指示は止まってしまうのでしょうか？

本稿では、ミリ秒単位で稼働状況を監視し、「追加APIコスト0円を死守したまま絶対に処理を止めない」多層フェイルオーバーと自動復帰（Self-Healing）アーキテクチャの全貌を解説します。

1. 多層フェイルオーバーの全体像（4段階のゼロコスト多層防御）

推論要求が発生した際、ルーターエンジン（model_router.py / llmroute.py）は以下の優先順位に従って自律的にノードを選定・迂回します。

階層（Tier） ノード / モデル 役割と特徴 APIコスト
Tier 0-A（第一候補） Strata (z790-al) RTX 4070TiS + 3060。秒速45〜80トークンの超高速推論。 完全 $0.00
Tier 0-B（第二候補） AMD BC-250 40CU APU。Colibri（35B MoE）/ Mistral-Nemo（ポート8080）。 完全 $0.00
Tier 0.5（第三候補） OpenRouter Free MiniMax M3.1 Flash（1Mコンテキスト）、Nemotron等の動的無料枠。 完全 $0.00

2. シナリオ別の挙動：落ちた時・ビジーの時に何が起きるか？

① Strata（z790-al）がダウンまたはビジーの場合

Strataはプロキシ経由でポート 47832 を提供しています。リクエスト発行時に2秒のヘルスチェック（/v1/models）を行い、応答がない場合や HTTP 502/503 が返った場合、ルーターは即座に以下を実行します：

  • 中小規模タスク（入力 ≤ 12,000トークン）: 即座に AMD BC-250（ポート8080または8008）へリクエストをバイパス。
  • 大規模コンテキスト（長文要約・コードベース解析）: BC-250のメモリ枠を超えるため、OpenRouterの MiniMax M3.1 Flash（1Mコンテキスト無料枠） へ自動迂回。

これにより、ユーザーやエージェントはStrataの停止を意識することなく、追加コスト0円のまま回答を受け取ることができます。

② BC-250がダウンまたはビジーの場合

小規模基板であるBC-250では、長大なプロンプトや極端な負荷によってプロセスやTailscale接続が一時的に途切れるリスクがあります。ここで威力を発揮するのが「死活キャッシュ（Alive Cache）」です。

# 死んでいるノードへの無駄な10秒タイムアウトを防止する死活キャッシュ
def bc250_alive(ttl=300):
    global _bc250_last_check, _bc250_cached_alive
    now = time.time()
    if now - _bc250_last_check < ttl:
        return _bc250_cached_alive
    try:
        # 2秒タイムアウトでポート疎通確認
        s = socket.create_connection(("100.79.26.62", 8080), timeout=2)
        s.close()
        _bc250_cached_alive = True
    except (socket.timeout, ConnectionRefusedError, OSError):
        _bc250_cached_alive = False
    _bc250_last_check = now
    return _bc250_cached_alive

もしBC-250の応答が切れた場合、5分間はBC-250への接続試行を自動スキップし、毎リクエストで発生する10秒間のタイムアウト待ち時間を完全にゼロ化します。即座にStrataやOpenRouterへフォールバックされるため、切り替えオーバーヘッドは実測わずか5.9秒です。

3. Systemd による自動自己復帰（Self-Healing）の実装

プロセスが予期せぬエラーやOOMでクラッシュした場合、手動でSSHログインして再起動するのは非効率です。BC-250上のColibri推論サーバーは、LinuxカーネルのSystemdサービスとして常駐化されており、クラッシュを検知すると5秒以内に自動復旧します。

# /etc/systemd/system/colibri.service の自動復帰ディレクティブ
Restart=on-failure
RestartSec=5
LimitNOFILE=65536

これにより、万が一プロセスが終了しても、5秒の待機を経て自動的に再起動され、クリーンなメモリ空間でポート8008が復旧します。

4. 総括：自宅GPUクラスタを真の「インフラ」にするために

単一のGPUやPCに依存したローカルLLM運用は、クラッシュやビジーによって簡単に破綻します。しかし、以下の3点を組み合わせることで、商用クラウドに匹敵する高可用性を実現できます：

  1. 異種ハードウェアの相互補完（Strata 4070TiS × BC-250）
  2. 無駄な待機時間を生まない死活キャッシュとフェイルオーバー設計
  3. 万が一の自宅ノード全滅時でもAPI課金を防ぐ「クラウド無料枠（OpenRouter Free）」の安全弁

これにより、私たちのAIリビングラボは「コスト0円」と「絶対に落ちない安定性」を両立した自律基盤として24時間稼働を続けています。
