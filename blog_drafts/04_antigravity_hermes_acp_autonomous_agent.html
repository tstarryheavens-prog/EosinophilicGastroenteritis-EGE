1. なぜ「Antigravity」に「Hermes Agent」の頭脳が必要だったのか？

Google Antigravityは、VS Codeをベースにした次世代のAI-first IDE／デスクトップ環境です。洗練されたUI、軽快な動作、強力なマルチエージェントやMCP連携機能を持ち、まさに「日常のメイン作業ウィンドウ」として最高のポテンシャルを持っています。

しかし、一般的なAIアシスタントにはどうしても共通の弱点がありました：

❌ 従来のAIアシスタント
「〜のように実装すれば動きますよ」と計画やコード片（スタブ）を提示して満足してしまう。実行やエラー調査は人間に丸投げ。
⭕ 求める自律エージェント
コードを書き、テストを走らせ、ビルドを確認し、エラーが出たら勝手に直して「動く成果物」として完了報告してくれる。

そこで目をつけたのが、オープンソースコミュニティ（Nous Research）が開発する最強の自律型エージェント「Hermes Agent」でした。
Hermes Agentには、「Finishing the Job（仕事を最後までやり切る）」「No Filler（無駄口やお世辞を言わない）」「自己反復・自己修復」という、職人のような鋼の哲学が根付いています。

「Antigravityの最高のメインウィンドウに、Hermes Agentの妥協なき頭脳を合体させれば、最強の自立型AIエージェントができるのではないか？」
これが今回の挑戦の始まりでした。

2. ACP (Agent Client Protocol) × MCACP で繋ぐ次世代アーキテクチャ

異なるAIエージェント同士を繋ぐとき、これまでは専用プラグインを書くのが大変でした。しかし、AI業界にはいま2つの重要標準プロトコルがあります：

  • MCP (Model Context Protocol)：Anthropicが提唱した、AIと「外部ツール・データ」を繋ぐUSB-Cのような規格。
  • ACP (Agent Client Protocol)：エディタ（IDE）と「自律AIエージェント（Hermes等）」を繋ぐ、エージェント版LSP（Language Server Protocol）規格。

AntigravityはネイティブでMCPをサポートしています。そこで今回は、MCPとACPを相互変換する公式ブリッジ`mcacp`を導入しました！

+---------------------------------------------------------------+ | Antigravity 2.0 (メインウィンドウ / Chat UI) | +---------------------------------------------------------------+ | MCP Protocol (stdio) v +---------------------------------------------------------------+ | MCACP Bridge (`mcacp`) | +---------------------------------------------------------------+ | Agent Client Protocol (ACP over stdio) v +---------------------------------------------------------------+ | Hermes Agent (`hermes acp` / Nous Research) | | - 自律的思考ループ (Autonomous Reasoning Loop) | | - 永続メモリ・ツール実行・自己反復・ローカル実行 | +---------------------------------------------------------------+

Antigravityのグローバル設定（`~/.gemini/config/mcp_config.json`）に`mcacp`を登録したことで、Antigravityのメイン画面から直接、Hermes Agentのセッション初期化、プロンプト送信、ストリーミング思考の受信、ツール実行イベントの監視がシームレスに行えるようになりました。

3. 魂の移植：Hermes SOUL と「Finishing the Job（完遂原則）」

単に外部ツールとしてHermesを呼べるだけでは不十分です。
「Antigravity自身が、Hermesのような自立型思考を持つこと」こそが本丸です。

そこで、Antigravityのマシン最上位ルールである~/.gemini/config/GEMINI.mdを新設し、Hermes Agentの「魂（SOUL）」と「行動プロトコル」を直接注入しました：

📜 Antigravity 自律行動規範（GEMINI.mdより抜粋）
  • Direct & Proactive: 「ご質問ありがとうございます！」などの無駄な相槌をゼロにし、質問の重みに応じた率直で本質的な回答をする。
  • Finishing the Job: 成果物は「本物のツール実行ログに裏付けられた動く成果物」でなければならない。スタブ（TODO）や計画だけで停止することを禁止。
  • Autonomous Self-Healing: コマンドやビルドが失敗しても手を挙げず、エラーログを自律分析して別アプローチを自ら試行・自己修復する。
  • Strict Truthfulness: 架空のデータや捏造結果を絶対に作らず、実測ログと客観的事実のみを報告する。

これにより、Antigravityは「指示されたら計画を立てて人間に確認するアシスタント」から、「ゴールを与えられたら最後まで自分で走り切る頼れる自立型パートナー」へと完全に覚醒しました。

4. Usage（APIトークン）を自律節約する「4階層モデルルーティング（Tier 1〜4）」

自律型エージェントを本気で運用すると、あっという間に直面するのが「APIトークン・クォータ枯渇問題」です。
何十ステップも自律思考させたり、大きなモデル（Pro）で単純なgrep検索をさせたりすると、あっという間に利用制限に達してしまいます。

そこで設計したのが、難易度とトークン経済性を両立させる「自律型4階層モデルルーティング（Tier 1〜4）」です！

そして何百回も試行錯誤が必要なタスクは、ローカルPCのGPU（LM Studio / Ollama）で動くHermes Agentにオフロードすることで、クラウドAPI費用を1円も消費せずにやり切るという究極の布陣が完成しました。

5. 0.05秒の電脳ゲート：Parallel Constrained Decoding (PCD) の完全統合

「でも、AI自身が『このタスクはTier 1かTier 3か』をどうやって正確に判断するの？」
ここで大活躍するのが、先日我が家の環境に導入した「Parallel Constrained Decoding（PCD）」です！

通常、LLMに分類を頼むと「うーん、これはやや複雑なタスクですね…」と長文を返してきて遅く、判断がブレます。
PCDは、ブロードキャストKVキャッシュ技術を用い、指定したEnum（選択肢）やBoolean（真偽値）だけを並列拘束デコードし、0.05秒・100%スキーマ準拠・確率スコア（Confidence Score）付きで出力します。

⚡ PCDの2大役割
  1. モデル選定ゲート (`extract_structured_decision`): タスクを受けた瞬間、難易度（`TIER1`〜`TIER4`）と委譲フラグを瞬時に判定。
  2. 自己修復・エラー分類ゲート (`classify_incident`): ビルドやテストがコケた瞬間、深刻度（P0〜P3）と原因コンポーネント（COMPILER / CONFIG / RUNTIME等）を即座に分類し、最適な修復行動を一瞬で決定。

PCDが「電脳の反射神経」として組み込まれたことで、Antigravityは一切迷うことなく、最適なモデル選定とエラー自己修復を実行できるようになりました。

7. まとめ：どのチャットを開いても全自動で動く未来の暮らしへ

しかも、この仕組みの素晴らしいところは、「どのチャットウィンドウを開いても、勝手に全自動で機能する」という点です。

マシン全体の最上位スコープ（~/.gemini/config/GEMINI.md）にルールを配置したため、特別なコマンドを打つ必要も、毎回プロンプトをコピペする必要もありません。
新しくチャットを開いて、

「この機能を追加して、テストとビルドまで終わらせておいて」

と一言つぶやくだけで、Antigravityが：

  1. PCDで難易度を0.05秒判定し、適切なモデルを選択（クォータ節約）
  2. 10年分のナレッジを参照しながらコードを自律実装
  3. テストとビルドを実行し、エラーが出れば自律自己修復
  4. 完成したらGitHubに自動コミット＆プッシュして完了報告

……という一連のフローを、すべて自立してやり切ってくれます。
