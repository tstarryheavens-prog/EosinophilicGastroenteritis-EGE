1. なぜ「Laya（非自己回帰判定）」×「ローカルLLM」なのか？

従来のLLMによるタスクルーティングは、自己回帰生成（1トークンずつ順番に文字を出力する方式）に依存していたため、JSON出力や単純な二値判定であっても 200ms〜1,000ms の遅延とハルシネーションリスクを伴いました。

これに対し Laya（convaiinnovations/laya） は、テキスト生成を行わず「単一のフォワードパス（1-pass）」で選択式（Choice）・スコア評価（Score）・真偽確率（Noul）を出力するエンコーダベースの判定エンジンです。

2. Dual-GPU 負荷分散アーキテクチャとFastMCP統合

Layaによる超高速ルーティングをMCP（Model Context Protocol）ツールとして公開することで、GeminiアプリやAntigravity IDE、Hermes Agentが「このタスクは軽量か重量か」を35ms以内に自動判定し、最適なGPUノードへ振り分けます。

  • Tier 0（Laya <35ms ルーター）: タスクの難易度、機密性、言語、出力形式を単一フォワードパスで判定（CPUまたは軽量VRAM常駐）。
  • Tier 1（サブGPU: RTX 3060 12GB）: 定型要約、記事ドラフト、yomiyasu日本語推敲、コード整形（52.2 tok/s）を担当。
  • Tier 2（メインGPU: RTX 4070 Ti SUPER 16GB）: 125B級MoEモデルのオフロード推論、複雑なマルチファイルリファクタリング、長文分析を担当。

3. ステップバイステップ実装：Laya-MCPサーバーの構築

#!/usr/bin/env python3
from mcp.server.fastmcp import FastMCP
import time

mcp = FastMCP("laya-router", instructions="35ms以内でタスク難易度を判定し最適なGPUノードを割り当てる")

@mcp.tool()
def route_task(prompt: str, context_size: int = 0) -> dict:
    start = time.perf_counter()
    # 実際の環境では laya.predict() により Choice / Score を単一フォワードパスで算出
    is_complex = context_size > 8000 or any(k in prompt for k in ["設計", "リファクタ", "論文", "アーキテクチャ"])
    target_gpu = "RTX_4070_Ti_SUPER_16GB" if is_complex else "RTX_3060_12GB"
    elapsed_ms = (time.perf_counter() - start) * 1000
    return {
        "target_node": target_gpu,
        "confidence": 0.94 if is_complex else 0.89,
        "routing_latency_ms": round(elapsed_ms, 2)
    }

if __name__ == "__main__":
    mcp.run()
