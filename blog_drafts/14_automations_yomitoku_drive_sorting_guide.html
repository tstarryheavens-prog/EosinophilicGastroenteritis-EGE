本記事では、この自動化を実現するために「どんな機能が必要だったのか」「どういう判定仕様にしたのか」「具体的な導入・適用手順」、そして「実際に毎日動かしてみて感じた本音の感想」を包み隠さずまとめました。

1. 全体の仕組み（アーキテクチャ）

全体構成は、「クラウドストレージ（Google Drive）」「定期自律エージェント（Antigravity Automations）」「日本語解析エンジン（YomiToku）」「操作実行スクリプト（sorter.py）」の4層で連携しています。

1
トリガー：Antigravity Automations（Sidecar Cron）

CRON_TZ=Asia/Tokyo 0 12 * * *（毎日正午12時）に自動起動。バックグラウンドで新しいエージェントセッションを開始し、タスクを指示します。

2
検知・取得：Google Drive API（mcp-google-multi経由）

「90_未整理ファイル」フォルダを走査。投入されたPDFファイルや、ZIP解凍後の一時フォルダ内の全ファイルをリストアップし、ローカル作業領域に一時ダウンロードします。

3
解析：YomiToku 日本語Document AI

PDFの1ページ目を画像化し、文字認識・表構造認識を実行。Markdown形式のテキストに変換して、文書内に含まれる「年月」「組織名」「書類タイトル」「個人名」を高速抽出します。

4
リネーム・仕分け・クリーンアップ：Drive API

ルールエンジンで生成した新ファイル名へ更新し、該当する家庭機能フォルダへ移動（親フォルダ付け替え）。空になった一時フォルダは自動でゴミ箱へ移動して整理を完了します。

2. 自動化に必要だった5つの重要機能

単なる「PDF名のリネーム」ではなく、家庭で破綻なく運用するためには以下の5つの機能が不可欠でした。

① 階層型スキャン＆一時フォルダ回収機能

ユーザーはファイルを直接ドライブ直下に置くだけでなく、「ZIPを展開したフォルダごと放り込む」ケースが多々あります。直下のファイルだけでなく、子フォルダの中身も再帰的に検知し、処理後に空フォルダをゴミ箱へ片付ける機能が必要です。

② 日本の帳票に強いローカルOCR（YomiToku）

海外製OCRでは、給与明細の細かい表組みや、縦書きの年金通知書、傾いた領収書で文字化けが発生します。ローカルで動作するYomiTokuを使うことで、API費用をかけずに高精度な日本語テキストが得られます。

③ 日付の正規化抽出（西暦・和暦・短縮表記対応）

書類によって「2026年4月」「2026-04-15」「2604」「2411」など日付の書き方がバラバラです。正規表現を用いて一律YYYYMMまたはYYYYMMDDの命名フォーマットに揃えます。

④ ドメイン分類ルール（人物判定・書類種別判定）

同じ給与明細でも「夫」と「妻」で保存先フォルダが分かれます。本文中の氏名やキーワードから「誰の給与か」「通常給与か賞与か」を識別し、的確なサブフォルダIDへ振り分けます。

⑤ 最小権限設定（Sidecar permissions）

バックグラウンドで無人実行されるため、アクセス権限は必要最小限のコマンド（python3, node）とトークン・スクリプトパスに限定し、安全性を確保します。

4. 実際の適用手順（セットアップの流れ）

ステップ①：仕分け処理スクリプト（sorter.py）の準備

YomiTokuでPDFの1ページ目を読み、テキストを正規表現で判定してDrive上の親フォルダを付け替えるスクリプトです。外部APIを使わないため完全無料で運用できます。

環境構築手順：

python3 -m venv ~/.venv/drive-sorter
source ~/.venv/drive-sorter/bin/activate

# 必要なパッケージのインストール
pip install yomitoku google-api-python-client google-auth-oauthlib pypdf

仕分けルール判定スクリプトのコアコード（sorter.py）：

import re
from datetime import datetime

def extract_date_from_text(text: str) -> str:
    """テキストから年月（YYYYMM）を抽出して正規化"""
    m = re.search(r'(20\d{2})[\s年/\-\.](\d{1,2})', text)
    if m:
        year, month = m.group(1), int(m.group(2))
        return f"{year}{month:02d}"
    return datetime.now().strftime("%Y%m")

def classify_document(ocr_text: str, filename: str) -> dict:
    """OCRテキストから書類種別と保存先を自動判定"""
    text = (filename + " " + ocr_text).lower()
    date_str = extract_date_from_text(ocr_text)

    # 給与・賞与明細
    if any(k in text for k in ["給与明細", "賃金明細"]):
        if any(k in text for k in ["賞与", "期末手当"]):
            return {"category": "bonus", "new_name": f"{date_str}_賞与明細.pdf"}
        return {"category": "salary", "new_name": f"{date_str}_給与明細_本人.pdf"}

    # クレジットカード請求書
    if any(k in text for k in ["カード", "ご利用代金明細"]):
        return {"category": "card_bill", "new_name": f"{date_str}_カード利用明細書.pdf"}

    return {"category": "unclassified", "new_name": f"{date_str}_{filename}"}

  • 「書類をどこに保存するか」悩む脳のメモリがゼロになった： とりあえず未整理フォルダに放り込めば、正午に全部きれいに片付いている快感。

  • クラウドAIを使わないので完全無料＆セキュア： 個人情報満載の給与明細や医療データを外部APIに送らず、ローカルのYomiTokuで処理できる安心感。

⚠️ 運用上の注意点・ハマりどころ

  • PDFの全ページを読むと重い： 10ページのPDFを丸ごとOCRすると時間がかかるため、「1ページ目だけを解析して書類特定する」割り切りが高速化の鍵。
  • Google Driveのトークン有効期限： 定期実行がエラーで止まらないよう、認証トークンの自動更新管理が必要。
  • 未知の書類はフォールバック先へ： ルールに該当しない書類を無理にリネームせず、「01_家計/請求明細」などの共通置き場に残す設計が安全。
