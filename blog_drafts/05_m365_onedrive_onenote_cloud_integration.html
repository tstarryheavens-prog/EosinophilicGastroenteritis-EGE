01. なぜローカル同期フォルダでは駄目なのか？（Files-On-Demandの罠）

「MacにOneDriveアプリが入っているなら、ローカルの同期フォルダ（~/Library/CloudStorage/OneDrive-...）をAIに読み込ませればいいのでは？」と思うかもしれません。

しかし、ここにはmacOS特有の大きな技術的障壁が存在します。

⚠️ APFS Dataless File（オンデマンドファイル）の仕様
macOSのOneDriveは、Macのストレージ容量を節約するために「ファイル名やメタデータだけをMacに置き、実データはクラウド上に置いたまま」にするFiles-On-Demand（オンデマンド機能）が標準で有効になっています。
この状態のファイルは、ターミナルやAIが grep や view_file で中身を読もうとしても「0バイトの空ファイル」または実体なしとして扱われ、中身の全文検索が一切できません。

さらに、OneNote for Macはノートデータを暗号化されたローカルキャッシュに保存しており、Apple Events / AppleScript 経由でのDOM操作も提供されていません。そのため、ローカルからセクションやページ本文を安全に抽出する手段がありませんでした。

解決策はただひとつ、「Microsoft Graph API を叩いてクラウドサーバー上の本尊データと直接おしゃべりする」ことでした。

02. アーキテクチャ設計：@softeria/ms-365-mcp-serverの採用

Microsoft Graph APIと連携するMCPサーバーとして、オープンソースで最も実績と柔軟性のある @softeria/ms-365-mcp-server を採用しました。

このサーバーには、AIエージェント運用において決定的に重要な2つの強みがあります：

🎯 1. プリセットによるツール絞り込み
M365全体（Teams、SharePoint、Outlook、Planner等）を読み込むと300以上のツールが登録され、AIのコンテキストを大量に浪費します。
--preset files,onenote を指定することで、必要な34ツールだけに限定し、省エネ＆高速動作を実現できます。
🔒 2. 安全なローカル暗号化キャッシュ
認証トークンは平文で保存されるのではなく、macOSのセキュアな ~/Library/Application Support/ms-365-mcp-server 配下に暗号化保存されます。一度認証すれば、次回以降は自動更新されます。

03. 【手順1】Microsoft Entra ID（Azure）でアプリ登録と権限設定

自分専用のクライアントIDを発行し、セキュアに接続するためのEntra ID（旧Azure AD）設定手順です。

  1. Microsoft Entra 管理センター（アプリの登録）にアクセスし、Microsoftアカウントでログインします。
  2. [新規登録] をクリックします。
    • 名前: Antigravity-M365-Bridge（任意の分かりやすい名前）
    • サポートされているアカウントの種類: 「任意の組織ディレクトリ内のアカウント (任意の Microsoft Entra ID ディレクトリ - マルチテナント) と個人用の Microsoft アカウント (Skype、Xbox など)」を選択
  3. 登録完了後、概要画面に表示される 「アプリケーション (クライアント) ID」 をメモします。
  4. 左メニューの [管理] > [認証] を開き、[プラットフォームを追加] をクリック。
    • [モバイル アプリケーションとデスクトップ アプリケーション] を選択
    • リダイレクト URI で https://login.microsoftonline.com/common/oauth2/nativeclient および http://localhost にチェックを入れて保存
    • 下部の「詳細設定」にある 「パブリック クライアントのフローを許可する」 を 「はい」 に設定して保存
  5. 左メニューの [管理] > [API のアクセス許可] を開き、[アクセス許可の追加] > [Microsoft Graph] > [委任されたアクセス許可] を選択。
    • Files.ReadWrite（OneDriveファイルの検索・読込・書込）
    • Notes.Create（OneNote作成）
    • Notes.Read（OneNote読込）
    • Notes.ReadWrite（OneNote編集）
    を追加します。

04. 【手順2】mcp_config.json への登録（個人アカウント必須パラメータ）

Antigravity（またはClaude Desktop等）のMCP設定ファイル（~/.gemini/config/mcp_config.json 等）にサーバー定義を追加します。

💡 【超重要ノウハウ】個人アカウント特有の invalid_grant 回避策
個人用Microsoftアカウント（hotmail.com, outlook.jp等）を使用する場合、既定のオーソリティ（common）ではリフレッシュトークン更新時に invalid_grant エラーが発生することがあります。
これを防ぐため、環境変数に必ず "MS365_MCP_TENANT_ID": "consumers" を指定してください！ 
{
  "mcpServers": {
    "ms-365": {
      "command": "/opt/homebrew/bin/npx",
      "args": [
        "-y",
        "@softeria/ms-365-mcp-server",
        "--preset",
        "files,onenote"
      ],
      "env": {
        "MS365_MCP_CLIENT_ID": "あなたのクライアントIDをここに入力",
        "MS365_MCP_TENANT_ID": "consumers"
      }
    }
  }
}

05. 【手順3】Device Code フローによる安全な初回認証

ターミナルからワンタイムで初回認証を実行します。ブラウザで認証URLを開いて表示された8桁コードを入力するだけの簡単なステップです。 

# 初回ログインコマンドを実行
MS365_MCP_CLIENT_ID="あなたのクライアントID" \
MS365_MCP_TENANT_ID="consumers" \
npx -y @softeria/ms-365-mcp-server --preset files,onenote --login

実行すると次のような案内が出力されます：

    To sign in, use a web browser to open the page https://www.microsoft.com/link and enter the code XXXXXXXX to authenticate.

ブラウザで https://www.microsoft.com/link を開き、表示されたコードを入力してサインインとアクセス許可を承認すれば完了です！トークンが安全に暗号化保存され、以降は常時AIからアクセス可能になります。
