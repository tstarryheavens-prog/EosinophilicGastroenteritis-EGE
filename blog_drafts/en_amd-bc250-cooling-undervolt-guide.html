1. The Crisis: 101.4°C APU and 85°C M.2 SSD Out-of-the-Box

Right after successfully unlocking all 40 Compute Units (2,560 stream processors) and 16 CPU threads on our ~$150 AMD BC-250 board running Fedora 45 Server, running sensors revealed an alarming thermal state:

BASH (Stock Thermal Readings Under Idle/Light Load) 
k10temp-pci-00c3
Tctl:        +101.4°C   <-- CPU boiling above boiling point!

nvme-pci-0300
Composite:    +84.8°C  (crit = +94.8°C) <-- NVMe drive throttling!

amdgpu-pci-0100
vddnb:         1.22 V   <-- Dangerously high default voltage
edge:        +100.0°C   <-- GPU silicon hit 100°C!
PPT:          68.82 W

Both the CPU and GPU were pegged at 100°C–101°C, with the M.2 NVMe SSD dangerously close to its critical shutdown threshold of 94.8°C. Continuous 24/7 operation in this state would severely degrade the hardware and cause severe thermal throttling during LLM inference.

2. Why Does the BC-250 Overheat?

Our diagnostic revealed two root causes rooted in the BC-250's origin as an industrial crypto-mining board:

  1. Excessive Factory Voltage Margin: Designed to run reliably in harsh mining farms without Silicon Lottery variance failures, the factory BIOS defaults to an aggressive 1.22V, which is comparable to heavy overclocking profiles.
  2. Locked Fan PWM in Default Linux Kernels: The onboard Nuvoton NCT6686 Super-I/O chip defaults to the in-tree nct6683 driver, which mounts all PWM registers as read-only. The cooling fan remained locked at a quiet ~820 RPM regardless of load.

3. Step 1: Building and Installing the NCT6687d Kernel Driver

To regain write control over the motherboard's PWM fan headers, we compile and install the out-of-tree nct6687d driver:

BASH (Compile & Install NCT6687d) 
# 1. Unload the legacy read-only module
sudo modprobe -r nct6683

# 2. Clone and build nct6687d
cd ~
git clone https://github.com/Fred78290/nct6687d.git
cd nct6687d
make -j16

# 3. Install and load
sudo make install
sudo depmod -a
sudo modprobe nct6687

# 4. Persist on boot and blacklist the conflicting nct6683 driver
echo 'nct6687' | sudo tee /etc/modules-load.d/nct6687.conf
echo 'options nct6687 force=true' | sudo tee /etc/modprobe.d/nct6687.conf
echo 'blacklist nct6683' | sudo tee /etc/modprobe.d/blacklist-nct6683.conf

4. Step 2: SMU Dynamic Undervolting (Curve Scale = -35)

The breakthrough comes from communicating directly with the AMD System Management Unit (SMU) using the open-source bc250_smu_oc library:

BASH (Clone SMU Tuning Library) 
cd ~
git clone https://github.com/bc250-collective/bc250_smu_oc.git

We apply four interlocking safety and efficiency configurations simultaneously:

  • Hardware Safety Trip (85°C Max): smu.q3_0x8b_set_cpu_max_temperature(85) and smu.q3_0x8c_set_gpu_max_temperature(85) ensure the hardware never breaches 85°C.
  • Disable Extra Voltages: smu.disable_extra_cpu_gpu_voltage(True) prevents the motherboard from injecting artificial voltage spikes.
  • Dynamic F-V Curve Undervolt (scale = -35): smu.q3_0x50_scale_f_vid_curve(-35) shifts the voltage curve down across the entire frequency range while allowing dynamic scaling.
  • Boost Frequency Ceiling (3,500 MHz): smu.q3_0x8f_set_max_cpu_boost_clk(3500) caps the peak frequency at the PS5's native 3.5 GHz sweet spot.

7. Production Deployment: systemd Service Configuration

Deploy the optimizer as a persistent systemd service so every cold boot automatically applies the optimal curve:

BASH (Setup Persistent Service) 
sudo tee /usr/local/bin/bc250-power-optimizer.py << 'EOF'
#!/usr/bin/env python3
import sys
sys.path.insert(0, '/home/bc250/bc250_smu_oc')
from bc250_smu import Bc250Smu

def main():
    try:
        smu = Bc250Smu(use_flock=True)
        smu.q3_0x8b_set_cpu_max_temperature(85)
        smu.q3_0x8c_set_gpu_max_temperature(85)
        smu.disable_extra_cpu_gpu_voltage(True)
        smu.q3_0x50_scale_f_vid_curve(-35)
        smu.q3_0x8f_set_max_cpu_boost_clk(3500)
        print('[BC-250] Power & thermal optimizer applied.')
    except Exception as e:
        print(f'[BC-250] Error: {e}', file=sys.stderr)

if __name__ == '__main__':
    main()
EOF

sudo chmod +x /usr/local/bin/bc250-power-optimizer.py

sudo tee /etc/systemd/system/bc250-power-optimizer.service << 'EOF'
[Unit]
Description=AMD BC-250 SMU Power & Thermal Optimizer
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/bc250-power-optimizer.py
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now bc250-power-optimizer.service
