1. なぜ従来のLLMで「条件分岐」をやってはいけないのか？

巨大な自己回帰型LLM（Autoregressive LLM）をエージェントの条件分岐やルーティングに用いる場合、次の構造的課題が生じます。

❌ 1. レイテンシの蓄積
出力が「A」か「B」の1文字であっても、プロンプト読み込みと自己回帰生成で1〜3秒消費。ループ全体が鈍重に。
❌ 2. トークンと費用の消費
分岐判定を1日に数百回〜数千回回すだけで、API料金が膨れ上がりRate Limitにも抵触。
❌ 3. 構文破綻（パース失敗）
引用符の閉じ忘れや不要なマークダウンの混入により、1%前後の確率でパース例外が発生。
❌ 4. 信頼できない「自信度」
通常のLLMの出力する確率は数学的に校正（キャリブレーション）されておらず、安全基準値として使えない。

この壁を打ち破るのが、「文章を一切生成せず、型定義された選択肢やスコアと、数学的に校正された確率だけを一発で返す」System 1 Decisionモデルです。

2. 世界標準「Laya」× 日本語最強「saihai-310m」の役割分担

🌐 Laya（convaiinnovations/laya）の強み

  • 非自己回帰型アーキテクチャ： 入力状態と型定義から、Metal GPU / MPS上でわずか33ミリ秒（0.033秒）で単一フォワードパス推論。
  • RLCD（校正済み強化学習）： 確率スコアが数学的に校正されており、「確信度90%」は真に90%当たる。
  • 高度なエコシステム： Python SDK、言語自動検出Router、MCPサーバーが公式で提供。

🗾 saihai-310m（采配 / hotchpotch氏作）の強み

  • 日本語特化の型付きDecisionモデル： 日本語リランカー ruri-v3-reranker-310m を基盤に、Bekko System One shared-prefix architecture を採用。
  • ローカルMPSで20〜30ms： Apple Silicon上で極めて高速に動作し、同サイズ帯の既存モデルを凌駕する日本語Choice精度。
  • 3つの型判定： 二者択一（Noul）、多肢選択（Choice）、段階スコア（Score）を正確に出力。
💡 組み合わせの狙い
公式Laya MCPサーバーを拡張し、日本語テキストを自動検知してsaihai-310mへ透過ルーティング。クライアント（エージェント側）は何も設定を変えずに、日本語はsaihai、英語はLayaという最強のハイブリッド推論の恩恵を受けられます！

Step 2: saihai-310m 推論エンジンの作成 (saihai_engine.py)

JSON Schemaをsaihaiの形式へマッピングし、MPS上で推論するモジュールです。 

import re, sys, time, torch
from typing import Any, Dict, Optional

_SAIHAI_MODEL = None
_SAIHAI_DEVICE = None

def is_japanese_text(text: str) -> bool:
    return bool(re.search(r"[\u3040-\u309F\u30A0-\u30FF\u4E00-\u9FFF]", text)) if text else False

def get_saihai_model():
    global _SAIHAI_MODEL, _SAIHAI_DEVICE
    if _SAIHAI_MODEL is None:
        from transformers import AutoModel
        _SAIHAI_DEVICE = "mps" if torch.backends.mps.is_available() else "cpu"
        _SAIHAI_MODEL = AutoModel.from_pretrained(
            "hotchpotch/saihai-v1-310m",
            trust_remote_code=True,
            device=_SAIHAI_DEVICE,
            attn_implementation="sdpa",
        )
    return _SAIHAI_MODEL, _SAIHAI_DEVICE

def schema_to_saihai_questions(schema_dict: Dict[str, Any]) -> Dict[str, Any]:
    properties = schema_dict.get("properties", schema_dict)
    questions = {}
    for name, spec in properties.items():
        t = spec.get("type", "string")
        desc = spec.get("description", name)
        if t == "boolean":
            questions[name] = {"type": "noul", "instructions": f"{desc}の該当有無を判定する。"}
        elif t in ("enum", "string") and ("enum" in spec or "choices" in spec):
            choices = spec.get("enum", spec.get("choices", []))
            questions[name] = {"type": "choice", "instructions": f"{desc}を選択する。", "criteria": {str(c): f"{c}: 候補" for c in choices}}
        elif t == "integer" and "minimum" in spec and "maximum" in spec:
            questions[name] = {"type": "score", "instructions": f"{desc}のスコア評価。", "criteria": [f"レベル{i}" for i in range(spec["minimum"], spec["maximum"] + 1)]}
    return questions

def decide_with_saihai(context_str: str, schema_dict: Dict[str, Any]) -> Optional[Dict[str, Any]]:
    model, device = get_saihai_model()
    if not model: return None
    try:
        t0 = time.perf_counter()
        res = model.systemone({"state": context_str, "questions": schema_to_saihai_questions(schema_dict)}, show_progress_bar=False)
        dur = (time.perf_counter() - t0) * 1000
        values = {k: v.get("choice") or v.get("noul") or v.get("score") for k, v in res.get("answers", {}).items()}
        return {"status": "success", "engine": "saihai-310m", "parallel_result": values, "parallel_latency": f"{dur:.1f}ms"}
    except Exception as e:
        return None

Step 3: ハイブリッド Laya MCP サーバーの実装 (server.py)

公式LayaのMCPサーバーを継承し、laya_decide をオーバーライドします。 

#!/usr/bin/env python3
import json, os, sys
from laya.mcp.server import server, _ensure_router, _wrap, _GUARDRAILS, _router_or_error
from laya.mcp.tools import laya_decide as official_laya_decide
from saihai_engine import decide_with_saihai, is_japanese_text

@server.tool(
    name="laya_decide",
    description="Plan A Hybrid Engine: routes Japanese to saihai-310m and English to Laya. " + _GUARDRAILS
)
def hybrid_laya_decide_tool(state: dict, schema: dict, model: str = "auto", min_confidence: float | None = None) -> str:
    text = " ".join(str(v) for v in state.values() if isinstance(v, str)) if isinstance(state, dict) else str(state)
    if is_japanese_text(text):
        res = decide_with_saihai(text, schema)
        if res is not None:
            return json.dumps(res, ensure_ascii=False)
    router = _router_or_error()
    return _wrap(official_laya_decide, state=state, schema=schema, model=model, min_confidence=min_confidence, router=router)

def main():
    _ensure_router()
    server.run()

if __name__ == "__main__":
    main()

比較項目 従来のLLM（Claude / GPT-4o） Laya × saihai ハイブリッド
判定レイテンシ 1,500ms 〜 3,500ms 25ms 〜 35ms（約100倍高速）
消費トークン / 料金 500〜1,500 トークン/回 0 トークン（完全ローカル実行）
JSON構文エラー率 1〜3%（パース例外あり） 0%（原理的に構文破綻しない）
確信度の信頼性 主観的な文章 RLCD校正済み確率（厳密な実数値）

🛡️ 鉄壁の「ゲートキーパー設計」

確信度が 0.85以上なら即座に自動実行、もし 0.85未満なら「曖昧な状況」と判断して大型LLMに熟考させる という二層構えにすることで、安全性を1ミリも落とさずに平均処理時間を極限まで圧縮できます。

5. まとめ：エージェントの意思決定を「直感」に委ねよう

これまでのLLMエージェントは、すべての判断を「超大型で重厚な言語モデル」に丸投げしていました。その結果、エージェントは1歩進むごとに立ち止まり、長いJSONを読み書きしては貴重なAPI料金と時間を消費していました。

  • Laya が切り拓いた「33msの非自己回帰推論とRLCD校正済み確信度」
  • saihai（采配） が実現した「日本語特化の型付き判定力（ruri-v3ベース）」
  • 公式MCPサーバーのオーバーライド による「透過的なハイブリッド統合」

この3点が揃ったことで、AIエージェントの自律ループは全く新しい次元へと突入しました。
重厚な熟考（System 2）は真に創造的なコード作成や複雑な設計だけに温存し、日常の何千回もの分岐判定は、Layaとsaihaiの「直感（System 1）」に任せるべきです。
